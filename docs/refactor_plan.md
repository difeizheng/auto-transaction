## 二、核心断层诊断（5个关键问题）

### 断层 1：实时数据未接入交易循环（最严重）

**位置**：`run_paper_trading.py` 第 122 行

```python
# 当前代码：从本地 SQLite 取历史日线数据（不是实时价格）
df = data_manager.get_daily_quotes(ts_code, '20260101', current_date)
```

- `SinaClient`（实时行情模块）已实现但**从未被调用**
- 每次策略执行用的是昨天收盘价，无法反映今天真实市价
- **后果**：模拟盘数据与真实市场完全脱节

### 断层 2：策略信号时机错误

- 交易循环每 60 秒运行（盘中），但策略是**日线策略**
- 盘中会反复对同一只股票产生信号，导致重复建仓
- 无"今日已建仓"的状态管理机制

### 断层 3：持仓市值不更新

- `PaperBroker` 成交后持仓价格**冻结在成交价**
- Web 监控显示的盈亏是静态快照，不反映当前市价
- 无法观察真实的浮盈浮亏变化

### 断层 4：A 股 T+1 规则未实现

- `PaperBroker._simulate_fill()` 允许即时卖出
- A 股买入当日不可卖出（T+1），导致模拟盘与真实规则不符
- 会产生在真实环境中不可能执行的交易序列

### 断层 5：策略性能不达标，验证范围过小

| 指标 | 当前 v5.0 | 建议目标 |
|------|-----------|---------|
| 年化收益 | 3.20% | >10% |
| 夏普比率 | 0.35 | >0.8 |
| 胜率 | 42.31% | >50% |
| 测试股票数 | 5 只 | 30+ 只 |
| 历史回测周期 | 2 年 | 3~5 年 |

## 四、模块重构详细设计

### 模块一：数据管道重构

**现状**：手动脚本获取 + SQLite 静态存储
**目标**：自动化调度 + 实时价格注入

```
src/data_pipeline/
├── scheduler.py          # 数据调度器（盘前/盘中/盘后三个阶段）
├── realtime_feed.py      # 实时价格流（Sina + 腾讯双源互备）
├── daily_updater.py      # 每日收盘后自动更新日线（调用 Tushare）
├── data_cache.py         # 内存价格缓存（取代每次查 DB，减少延迟）
└── market_calendar.py    # A股交易日历（节假日、调休处理）
```

**核心改进点**：
- 盘前 8:30 自动拉取前一日数据并验证完整性
- 盘中每 10 秒轮询 Sina 更新实时价格到内存缓存
- 盘后 16:00 批量更新所有股票池日线数据到 SQLite
- 数据源故障自动切换（Sina → 腾讯财经）

### 模块二：策略执行引擎重构

**现状**：策略逻辑耦合在交易循环里
**目标**：策略与执行解耦，信号独立生成和记录

```
src/strategy_engine/
├── signal_scheduler.py    # 信号调度器（控制信号生成时机）
├── signal.py              # 信号数据结构（含有效期/置信度）
├── portfolio_optimizer.py # 仓位优化（等权/风险平价/Kelly）
└── strategies/
    ├── optimal_v5.py      # 现有最优策略（接口适配）
    └── benchmark.py       # 沪深300基准策略（对比用）
```

**信号数据结构设计**：

```python
@dataclass
class TradingSignal:
    ts_code: str          # 股票代码
    direction: str        # buy / sell / hold
    signal_date: str      # 信号生成日期（YYYYMMDD）
    execute_date: str     # 计划执行日期（T+1，YYYYMMDD）
    target_price: float   # 参考价格
    confidence: float     # 置信度 0~1
    strategy_name: str    # 策略名称
    reason: str           # 信号原因描述
    executed: bool        # 是否已执行
```

### 模块三：模拟交易引擎重构

**现状**：PaperBroker 即时成交、价格不更新
**目标**：模拟真实 A 股交易规则

```
src/paper_trader/
├── paper_engine.py        # 主引擎（替换 run_paper_trading.py）
├── account.py             # 账户管理（持仓/资金/T+1限制）
├── order_book.py          # 订单簿（限价/市价模拟成交）
├── position_tracker.py    # 持仓追踪（用实时价格持续更新市值）
├── settlement.py          # 每日结算（当日盈亏/净值计算）
└── performance.py         # 策略性能统计（日度/累计指标）
```

**必须实现的 A 股规则**：

| 规则 | 实现方式 |
|------|---------|
| T+1 买入限制 | 记录每笔买入的 `buy_date`，卖出前校验 |
| 涨跌停限制 | 检测价格是否达到 ±10%/±20%（ST），拒绝超价委托 |
| 集合竞价 | 9:25 集合竞价用开盘价成交 |
| 手续费 | 买入 0.03%，卖出 0.13%（印花税 0.1% + 佣金 0.03%） |
| 最小交易单位 | 100 股的整数倍 |
| 退市/停牌处理 | 持仓中的停牌股票标记为不可交易 |

### 模块四：性能追踪体系

**现状**：无系统性的策略 vs 基准对比
**目标**：每日自动计算并存储策略净值

```
src/performance/
├── daily_recorder.py      # 每日收盘后记录净值快照
├── metrics.py             # 计算夏普/最大回撤/信息比/胜率
├── benchmark.py           # 沪深300日收益率（基准对比）
└── report_generator.py    # 生成周/月度报告
```

**追踪指标**：

| 指标 | 计算周期 | 说明 |
|------|---------|------|
| 日净值 | 每日收盘 | 策略总资产 / 初始资金 |
| 日超额收益 | 每日收盘 | 策略日收益 - 沪深300日收益 |
| 累计收益率 | 实时 | (当前净值 - 1) × 100% |
| 最大回撤 | 滚动计算 | 净值历史最高到当前最低的跌幅 |
| 滚动夏普 | 每周更新 | 近 30 个交易日的年化夏普 |
| 胜率 | 每笔交易后 | 盈利笔数 / 总交易笔数 |
| 信息比率 | 每月 | 超额收益均值 / 超额收益标准差 |

### 模块五：Web 监控看板重构

**现状**：FastAPI + 静态 HTML，数据不实时
**目标**：WebSocket 实时推送，数据全面

```
web/
├── app.py                 # FastAPI + WebSocket 服务
├── api/
│   ├── portfolio.py       # 持仓 API（含实时价格）
│   ├── signals.py         # 信号历史 API
│   ├── performance.py     # 净值/指标 API
│   └── market.py          # 市场状态 API
└── static/
    └── index.html         # 单页应用（ECharts 图表）
```

**Dashboard 四个核心页面**：

1. **实盘面板** — 持仓列表 + 实时价格 + 浮盈浮亏（WebSocket 推送）
2. **信号面板** — 今日信号 + 历史信号执行情况 + 命中率
3. **绩效面板** — 净值曲线 vs 沪深300 + 夏普/最大回撤/胜率
4. **回测对比** — 历史回测指标 vs 当前实际模拟盘对比

## 六、进入实盘的准备标准

模拟盘运行期间需满足以下全部条件，方可考虑进入实盘：

### 量化指标

| 指标 | 最低标准 | 理想目标 |
|------|---------|---------|
| 模拟盘运行周期 | ≥ 4 周 | ≥ 3 个月 |
| 年化收益率 | > 8% | > 15% |
| 夏普比率 | > 0.8 | > 1.2 |
| 最大回撤 | < 15% | < 10% |
| 胜率 | > 50% | > 55% |
| 超额收益（vs 沪深300） | > 5% | > 10% |
| 连续亏损最长周期 | < 2 周 | < 1 周 |

### 系统稳定性指标

| 指标 | 要求 |
|------|------|
| 系统可用率 | > 99%（交易时段无崩溃）|
| 数据获取成功率 | > 99%（Sina 实时数据）|
| 信号执行率 | > 95%（信号生成后均能执行）|
| 钉钉通知延迟 | < 60 秒 |

### 运营检查项

- [ ] 熔断机制经过真实市场大波动测试
- [ ] 至少完整经历一次市场回调（沪深300单日跌幅 >2%）
- [ ] 所有异常情况均有日志记录和告警
- [ ] 手工能复现任意一笔交易的盈亏计算

## 七、风险提示

1. **数据源依赖风险**：Sina/Tushare 接口可能变更，需设计备用数据源
2. **过拟合风险**：当前策略只在 5 只股票上优化，扩大股票池后可能性能下滑
3. **市场环境变化**：2024~2026 A 股政策变化频繁，历史参数未必适用
4. **模拟盘与实盘差距**：冲击成本、流动性限制在模拟盘中无法完全还原
5. **T+0 陷阱**：部分ETF支持T+0，注意不要将ETF策略误用于个股
